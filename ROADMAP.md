## Contexto en una línea

El **código** es sólido para el piloto; lo que no escala todavía es la **topología** (un proceso en un droplet) y 3 decisiones estructurales (B1, B2, B4). Decisión: **migrar el panel a React + TS primero** (porque las features nuevas son UI-pesadas), corriendo la **cola durable (B1) en paralelo** porque es el hueco de fiabilidad más urgente. El panel y el backend están desacoplados por la API JSON `/api/panel/*` (costura estable) → se migra pantalla por pantalla sin riesgo.

- [x] ✅ **E1 — Timeouts en toda la superficie de red** (BLOQ-03). Módulo nuevo `src/red/timeouts.ts` (política en un solo lugar, todo ajustable por `.env` con defaults cortos). `new OpenAI()` pasaba a usar los defaults del SDK —**600 s de timeout × 3 intentos = hasta 30 minutos** colgado en una llamada— y ningún `fetch` pasaba `signal` (undici espera ~300 s por intento). Combinado con el worker **serial** (un job a la vez para todos los tenants), eso era head-of-line blocking global: una llamada colgada del cliente A congelaba la cola de B, C y D, con `cola pendiente=N` creciendo en logs que nadie mira. Ahora: OpenAI a 20 s con `maxRetries: 1` (la cola durable ya reintenta el job) y 45 s para Whisper (sube el audio); `AbortSignal.timeout` en los **11** `fetch` del proyecto — Graph API (envíos 15 s, media 30 s porque viajan bytes), Google Calendar/OAuth/Places (15 s) y los 3 de Embedded Signup. El techo de 28,55 s medido en la simulación en un turno **sin herramientas** era evidencia directa de esto.
- [x] ✅ **E2 — `seedTenants.ts` ya no pisa la config del cliente** (ALTO-08, el ítem 11 del bloque A). El script corre en **cada push a `main`** (`ci-cd.yml`) y hacía `onConflictDoUpdate` con **todos** los campos de `TENANT_FALLBACK_SELYON` (`horario`, `servicios`, `kb`, `instrucciones`, `tono`, `pais`) más un reset del `passwordHash` desde `.env`: si el dueño afinaba su base de conocimiento un martes, el próximo deploy —aunque fuera por un cambio de CSS ajeno— **le revertía todo** y su contraseña volvía a la vieja. Regla nueva: el INSERT siembra todo (bootstrap de un tenant que no existe), el UPDATE toca **solo infraestructura** (`phone_number_id`, `access_token` — lo que administramos nosotros y el dueño no puede editar); el usuario del panel pasó a `onConflictDoNothing` + `.returning()` para loguear si se creó o ya existía, y **su contraseña nunca se sobreescribe** (para resetear está el flujo del superadmin de Carril D 0.5). - [x] ✅ **E3 — No se ofrecen (ni se agendan) horarios pasados** (BLOQ-09 ✅ verificado + BLOQ-08).
